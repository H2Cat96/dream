# 绘梦星球高保真演示交互设计

## 背景
当前应用已经具备三页核心结构：梦境宇宙首页、过往梦境档案馆、释梦页。视觉氛围和信息组织已经成型，但仍有大量区域停留在“静态展示”层面：能看、但不能点；看起来像功能、但没有反馈。对于产品演示和体验验证，这会明显削弱原型的可信度。

本轮目标不是接入真实后端，也不是完成真实业务闭环，而是把现有界面提升为“高保真可演示原型”：所有看起来应该有行为的区域，都提供一段合理的假交互、假状态或假内容。

## 目标
把现有 App 补齐为一套可以完整演示的交互原型，满足以下标准：

1. 主要按钮、卡片、统计块、图标入口都具备点击反馈。
2. 每个页面都有至少一条完整的“点开 -> 查看 -> 返回”路径。
3. 假数据和假流程保持当前产品语境，不破坏“儿童 + 梦境 + 宇宙 + 绘本”的设定。
4. 不引入真实网络请求、真实录音、真实存储模型，只在前端完成可演示状态。

## 非目标
1. 不接入后端接口。
2. 不实现真实语音录制、识别与上传。
3. 不实现真实梦境编辑、删除、持久化。
4. 不新增复杂路由系统，优先在现有单页/弹层结构内完成。

## 设计原则

### 1. 假交互也要像真产品
每个假交互都需要具备清晰的触发、过渡、结束状态，避免“一点就弹个 toast”式的敷衍感。

### 2. 保持梦境语境
所有反馈内容都要服务于“绘梦星球”世界观，例如“昨夜提醒”“梦境档案”“星球成长”“释梦卡片”，而不是通用后台式语言。

### 3. 尽量在当前结构上扩展
现有页面结构已经较稳定，本轮优先通过弹层、抽屉、切换态、假数据联动丰富体验，避免大规模重构页面骨架。

### 4. 手机优先
所有新增交互必须以当前手机框尺寸为基准，确保弹层、抽屉、卡片、详情内容在单屏内合理显示。

## 页面范围

### 首页：梦境宇宙
首页当前优势是梦境星云氛围足够强，弱点是前景控件可用性偏弱。本轮补齐为“可探索 + 可记录”的演示页。

#### 新增交互
1. 通知按钮打开“昨夜提醒”抽屉。
2. 星云中的梦节点可点击，弹出梦境摘要浮卡。
3. 底部语音入口进入一段假的录音流程：待录音 -> 录音中 -> 转写中 -> 归档完成。
4. 星球成长进度卡点击后展示阶段说明面板。

#### 交互细节
- 通知抽屉内容包含：昨夜提醒、最近一次记录时间、一个“去讲梦”按钮。
- 梦节点摘要卡内容包含：梦标题、简短摘要、情绪标签、一个“查看档案”按钮。
- 假录音流程不接入真实麦克风，只通过定时状态推进和波形/文案变化模拟。
- 成长进度面板说明不同阶段（种子星、晨雾星、发光星球、梦境行星）的解锁条件和意义。

### 过往梦境：档案馆
档案馆当前视觉已经接近“馆藏”，但交互上大多仍是静态信息。本轮补齐为“能翻看、能筛选、能查看单条档案”的体验。

#### 新增交互
1. 馆藏概览三张指标卡可点击，切换下方的解释提示文案。
2. 梦境馆历继续保留日期选择，并让下方文案随日期标签变化更明显。
3. 档案陈列中的每张绘本封面卡可点击，展开档案详情弹层。
4. 标本抽屉中的每个意象卡可点击，展开单意象说明。

#### 交互细节
- 馆藏概览的三种状态分别对应：高频意象、常见情绪、本周新增。
- 档案详情弹层展示：封面、标题、记录时间、情绪、标签、一段更完整的梦境描述、两个假按钮（继续整理 / 生成绘本）。
- 标本说明卡展示：意象名称、出现次数、最近一次出现时间、常见搭配意象、简短释义。
- 所有弹层仍然限制在手机框内。

### 释梦页
释梦页当前已经有月份、统计卡、分布图、塔罗牌，但不少区块还只是静态展示。本轮补齐为“能切换、能解释、能展开”的演示页。

#### 新增交互
1. 右上角设置按钮打开“释梦偏好”面板。
2. 三张统计卡可点击，打开对应说明弹层。
3. 月份切换会联动：统计值、分布图、意象标签、塔罗牌文案的假数据。
4. 保留现有塔罗牌展开与翻面行为。

#### 交互细节
- 设置面板包含假选项：解释风格、语气、是否展示重复意象、是否自动提醒。
- 统计卡说明弹层需要解释“记录总数”“已解释”“高频意象”的含义。
- 月份联动不追求完整数据模型，但每个月至少需要一组独立、肉眼可感知的变化。
- “你的梦里常出现的东西”卡片标题和塔罗牌内容应与月份切换保持一致。

## 信息架构
本轮不新增真正页面路由，而是在现有结构中增加局部状态：

1. 页面内弹层状态。
2. 页面内抽屉状态。
3. 假流程阶段状态。
4. 月份驱动的假数据映射。

这样可以让原型继续保持轻量，同时每一页都具备更完整的体验闭环。

## 技术方案

### 首页
- 在 `HomePage.tsx` 中新增局部状态管理：通知抽屉、当前选中的梦节点、假录音流程、成长说明面板。
- 复用现有 `framer-motion` 动画体系实现抽屉、浮卡、状态切换。
- 梦节点点击区域继续基于现有 canvas 布局的热点映射，不单独重写整套可视化。

### 档案馆
- 在 `DreamsPage.tsx` 中新增：概览激活状态、当前打开档案、当前打开标本。
- 使用现有卡片布局扩展详情弹层，而不是新增路由页。
- 保持当前日历、陈列、标本抽屉的结构不变，只增强点击响应与联动。

### 释梦页
- 在 `AnalyticsPage.tsx` 层新增月份数据源和设置面板状态。
- 将假数据按月份集中管理，再透传给 `MoodReflectionsCard`、`StatCard`、`DreamDistributionCard`、`WeekSelector`。
- `MoodReflectionsCard` 保持现有塔罗牌展开逻辑，只替换为月份驱动的数据。

## 假数据策略
为避免交互看起来“虽然能点但每次都一样”，本轮新增三套轻量假数据映射：

1. 首页梦节点数据：标题、摘要、情绪、标签。
2. 档案详情数据：长摘要、标签组合、推荐动作。
3. 释梦月份数据：统计值、主意象、分布比例、牌面解读。

这些数据都直接定义在前端常量中，不引入额外复杂数据层。

## 动效策略
1. 抽屉：从底部或顶部柔和滑入，避免全屏硬切。
2. 浮卡：透明度 + 位移 + 轻微缩放。
3. 语音假流程：通过波形、脉冲和按钮文案变化体现。
4. 档案详情与标本说明：卡片式浮层，保留当前玻璃/柔和阴影语言。
5. 月份切换：数字与图表局部过渡，不整体闪屏。

## 成功标准
本轮完成后，演示者可以完成以下路径：

1. 在首页点开通知、查看梦节点、触发一次讲梦假流程。
2. 在档案馆点日期、点馆藏概览、点开一张绘本档案、查看一个意象说明。
3. 在释梦页切月份、看统计变化、点统计卡、展开塔罗牌并翻面查看释义。

只要这三条路径都顺畅，原型就达到了“可完整演示”的目标。

## 风险与控制
1. 风险：状态过多导致单文件继续变大。
   控制：如果某页新增交互明显超过承载范围，应拆出小型详情/面板组件。

2. 风险：假交互过多导致页面显得杂乱。
   控制：所有新增入口都基于已有视觉元素，不再新增新的功能区块。

3. 风险：月份联动牵扯范围较广。
   控制：采用集中式假数据对象，避免每个组件各写一套独立逻辑。
